## Task navigation — MANDATORY for substantive work

For any task touching code or project structure:

1. Match the task against the repo map above (`When you need X`, `Entry points`).
2. Read `docs/info.md` if not yet read this session.
3. Read any developer-supplied briefs (paths mentioned in the request).
4. Open the matched entry points; read further code on demand only.
5. Form a plan, then proceed.

Never expect `<module>/docs/` folders — they don't exist here. Never bulk-scan the repo; navigate from the map.

**Classify silently and proceed by default.** Surface the navigation choice only when genuinely stuck. For explicit transparency, the developer can invoke `/fx-task <description>`.

## Context system

P-3 (Fenix) v4.0.0 layers:

- **This file** — identity, repo map, navigation rules. Survives compaction; keep it under ~200 lines.
- `.claude/rules/` — behavior rules. `git-workflow.md` and `fenix-conventions.md` are always-on (no `paths:` — do not add one). Per-module rules load when files matching their `paths:` globs are read.
- `docs/info.md` — authoritative project context (read once per session).
- `docs/DISCLAIMER.md` — session bootstrap messages (editable).
- `tasks/` — file-based artifacts for dev workflow runs.
- `docs-meta/runbook.md` — full operational details.
- `.fenix-manifest.json` — install record (used by /fx-uninstall).

## Slash commands

- `/fx-init` — generate or refresh the repo map + scaffold rules. `/fx-init upgrade` updates the kit.
- `/fx-info` — read-only status check.
- `/fx-task <description>` — explicit navigation with visible classification.
- `/fx-task new <description> [briefs:<path>]` — file-based dev workflow (architect → worker → tester).
- `/fx-agent rules` — list agent rules files for editing.
- `/fx-uninstall` — manifest-driven removal of all Fenix files.

## Subagents

Workers in `.claude/agents/`. Each has a `<name>-rules.md` sibling for editable behavior.

- `architect` — designs implementation plans (writes to task_dir/architect-plan.md).
- `worker` — executes plans (only writer of project code; writes worker-log.md).
- `tester` — reviews worker output (writes tester-review.md).

Run `/fx-agent rules` to edit any agent's behavior.
